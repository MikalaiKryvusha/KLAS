# План 27 (эпик 26, фаза 0) — Цена пробуждения: из чего складываются 34 секунды и чем их срезать

> **Создан:** 2026-08-16.
> **Родитель:** `plans/26_EPIC_hot_model.md`, фаза 0 · разведка — `researches/28`, `researches/29`.
> **Статус:** 🟡 написан 2026-08-16, ни один шаг не выполнен. Нужен СВОБОДНЫЙ GPU.
> **Вовне:** результат меняет форму эпика — если пробуждение упадёт до единиц секунд, фазы 2–3
> упрощаются или отпадают. Вывод обязан вернуться в мета-план.

## Вектор цели фазы

Пробуждение модели стоит 34–80 секунд, и мы НЕ ЗНАЕМ, из чего эти секунды состоят. Пока не знаем —
любое решение выше по эпику строится на догадке. Фаза отвечает на два вопроса: **куда уходит время**
и **сколько его можно вернуть, не написав ни строки сторожа**.

Правило порядка (якорь мета-плана): *«Если пробуждение упадёт с 34 с до единиц секунд, ценность
сложного сторожа резко падает — возможно, хватит поднять `ttl` и не строить ничего»*.

## Критерии приёмки фазы

| # | Критерий | Порог |
|---|---|---|
| **Ф0-1** | 34 секунды разобраны по стадиям (чтение файла · подгонка параметров · выделение VRAM · прогрев) | сумма стадий сходится с общим временем ±15% |
| **Ф0-2** | По каждому рычагу снято число на ОДНОЙ методике | 5 рычагов из таблицы ниже, ни одного «примерно» |
| **Ф0-3** | Лучший набор флагов зафиксирован в `llama-swap/config.yaml` и подтверждён замером | холодный TTFT после правки измерен, не предсказан |
| **Ф0-4** | В `plans/26` записано, изменилась ли форма эпика | абзац есть, с числом |

⚠️ Все замеры — `node tools/cold-ttft.mjs qwen3.8-27b --runs 2`, медиана. Одна методика на все
рычаги, иначе числа несравнимы.

## Шаги

### Ш1. Разобрать 34 секунды по стадиям
Якорь мета-плана: *«разбор 34 с по логу с метками времени»*.

- [ ] Поднять профиль вручную с `--verbose`, собрать лог загрузки в файл.
- [ ] Выписать метки времени между стадиями: открытие файла → чтение весов → `fit` → выделение
      буферов → warmup → «server ready».
- [ ] Записать таблицу «стадия → секунды → доля».

**Проверка наблюдением:** сумма стадий сходится с общим временем ±15% (Ф0-1). Не сходится — значит
время уходит туда, куда мы не смотрим, и это и есть находка.

### Ш2. NVMe против SATA
Якорь: *«модель на NVMe `D:` против SATA `F:`»*.

- [ ] Скопировать `Qwen3.8-27B-UD-Q3_K_XL.gguf` на `D:\KLAS_MODELS\` (12.52 ГиБ, свободно 77.8 ГБ).
- [ ] Профиль-двойник `qwen3.8-27b-nvme`, отличающийся ТОЛЬКО путём.
- [ ] Перезагрузить машину ЛИБО вытеснить файловый кеш — иначе меряем кеш, а не диск.
- [ ] Замер обоих, медиана из 2 прогонов.

**Проверка:** два числа в одной таблице. ⚠️ Без вытеснения кеша замер недостоверен — именно на этом
я уже обжёгся: 34 с против 80 с оказались разницей кеша, а не моделей.

### Ш3. `--load-mode dio` против `mmap`
Якорь: *«`--load-mode dio` против `mmap`»*.

- [ ] Замер с `-lm dio`, затем с `-lm mmap` (текущий по умолчанию).
- [ ] ⚠️ Реализация Direct I/O в апстриме под `__linux__`; на Windows ручка может не делать ничего.
      Отсутствие разницы — тоже результат, записать честно.

**Проверка:** разница в секундах либо явная запись «на Windows не действует».

### Ш4. Цена прогрева — `--no-warmup`
Якорь: *«`--no-warmup`»*.

- [ ] Замер с `--no-warmup`.
- [ ] ⚠️ Мерить именно TTFT, а не «server ready»: снятый прогрев переносит цену на первый реальный
      запрос, а не устраняет её. Если TTFT не изменился — рычаг фальшивый.

**Проверка:** TTFT до и после; вывод о том, реальный это выигрыш или перекладывание.

### Ш5. Цена подгонки параметров — `--fit off`
Якорь: *«`--fit off`»*.

- [ ] Замер с `--fit off` (у нас `-c`, `-ngl`, `-b`, `-ub` заданы явно — подгонять нечего).
- [ ] Сверить со стадией `fit` из Ш1.

**Проверка:** совпадение с долей стадии из Ш1 — две независимые оценки одного числа.

### Ш6. Ярус «файловый кеш» — измерить, а не предполагать
Якорь мета-плана: *«Три яруса вместо двух… средний ярус у нас уже дал 34 с против 80 с — стихийно»*.

- [ ] Замер сразу после перезагрузки машины (файл гарантированно не в кеше).
- [ ] Прогреть кеш чтением файла, замерить снова.
- [ ] Записать разницу — это и есть цена яруса RAM.

**Проверка:** три числа (холодный диск · тёплый кеш · тёплая VRAM) в одной таблице.

### Ш7. Зафиксировать лучший набор и вернуть вывод в эпик
- [ ] Собрать победившие флаги в профиль `qwen3.8-27b`, снабдить комментарием с числами.
- [ ] Замерить итог (Ф0-3).
- [ ] Дописать в `plans/26` абзац: изменилась ли форма эпика и как.

**Проверка:** `node tools/cold-ttft.mjs qwen3.8-27b --runs 2` на финальном профиле; число в конфиге.

## Риски фазы

| Риск | Чем гасим |
|---|---|
| Замеры несравнимы из-за файлового кеша | Ш2 и Ш6 явно управляют кешем; иначе любое число врёт (уже обожглись) |
| Карта занята владельцем | фаза целиком требует свободного GPU; не начинать, не спросив |
| Рычаг «работает» на одном прогоне | медиана из 2 прогонов, одна методика |
| `-c 49152` сидит на краю карты (свободно 390 МиБ) | если профиль не встанет с новыми флагами — снижать `-c` шагами по 8192 (≈272 МиБ KV) |

## Что фаза НЕ делает

Не пишет сторож, не трогает `ttl`, не детектирует игры. Это фаза измерения; её продукт — числа и
решение о форме эпика.
