## Вектор цели

- **Achieve:** голосовой эпик доведён до «испытано владельцем и живёт постоянно» — личный голос
  принят на слух, клоны звучат в резидентном рту вместо заглушек Silero, ассистент — служба, а не
  окно терминала.
- **Achieve:** LLM-ядро без нелегитимных сущностей — каждая модель реестра llama-swap имеет
  бенч-строки в `researches/02` и записанное решение владельца.
- **Maintain:** унаследованный долг вопросов вне «места вопросов» убывает: 10 → 0
  (`npm run guard:questions` печатает число каждым прогоном).
- **Avoid:** класс «работа по наитию» не повторяется — задача, проходящая тест тяжести
  (`AGENT_GUIDE.md` → «Дисциплина планирования»), исполняется только по лестнице
  `/plan-task` → `/plan-epic`; наработки чужих/слабых сессий проходят построчную приёмку (EXP-0063).

- Карта — **граф, не очередь**: бери первый НЕзаблокированный шаг, доступный в текущей ситуации.

## Риски (по ярусам Мёрфи)

**(а) Высшие — защита построена или строится:**
- 50 личных клипов утонут в ~10 000 синтетических → кратность дублирования печатается в конфиг,
  приёмка двусторонняя (А2; якорь plans/23 шаг 4).
- Служба Windows без звуковой сессии пользователя молча теряет микрофон/динамики → Ф2 закрывается
  только наблюдением на перезагруженной машине (В2).
- 🎮-шаг стартует на занятом GPU и меряет конкуренцию, а не модель (класс EXP-0033) → перед каждым
  🎮-шагом `nvidia-smi`, чужое не убивать.

**(б) Правдоподобные — план на случай срабатывания:**
- Пересобранный профиль кандидата (`-c 24576`) не встанет → шаг вниз на 20480 уже посчитан
  (`researches/26`, таблица VRAM).
- Вердикт А1 потребует перезаписи части клипов → стенд готов (`--audit --redo`), владельца звать
  только на перезапись брака.
- llama-swap не подхватит правку конфига на лету → перезапуск llama-swap штатным путём
  (`tools/klas.ps1`, механизм start-hidden.vbs).

**(в) Пустяковые — названы, чтобы помнить:**
- Ветка-бэкап отката удалена (была идентична a012aa4) — восстановление:
  `git branch backup-before-rollback-20260804-0900 a012aa4`.
- Часы маркера освежения прошлой сессии обгоняли реальные на ~15 мин — при сверках времени решает
  `date`, не чужая метка.
