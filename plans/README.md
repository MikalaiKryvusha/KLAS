# `plans/` — детальные планы шагов

Детальные планы отдельных кусков работы: шагов мастер-плана, конкретных фич, идей, багов,
исследований, процедур. **`MASTER_PLAN.md`** (корень проекта) — высокоуровневая дорожная карта;
`plans/` держит приближённые планы, реализующие её шаги. Один `NN_<name>.md` на план.

**Человеку (владельцу):** писать сюда не обязательно — планы обычно пишет агент. Можешь положить план,
если хочешь управлять тем, *как* что-то делается. Читай их, чтобы видеть намеченный подход агента до
того, как он его исполнит.

**ИИ-агенту:** перед нетривиальной работой напиши сюда короткий план и следуй ему. Каждый план
ОТКРЫВАЕТСЯ вектором цели + критериями приёмки — пишутся по `REQUIREMENTS_FRAMEWORK.md` и меняются
по мере работы. Сразу после H1 — линтуемая шапка-мета: **Создан:** · **Родитель:** · **Статус:**
(с вехами) · **Вовне:** (`AGENT_GUIDE.md` → Document header meta). Нумеруй файлы
(`NN_<name>.md`). Завершённый и проверенный план получает тег `DONE` в имени файла
(`git mv NN_x.md NN_DONE_x.md`) плюс статус-секцию. Справочные материалы (не закрываемые задачи)
DONE не помечаются.

**Именование — эпик виден в беклоге по имени файла.** Тяжёлая, составная, долгая работа планируется
**эпиком** (скилл: `/plan-epic`), и его файл несёт пометку: **`NN_EPIC_<name>.md`**. Файл эпика
держит пофазовое архитектурное описание дорожной карты — *и никакой операционной детализации*.
Детализация живёт у **детей**: по операционному плану на фазу (R&D, тестирование, имплементация,
приёмка), и каждый ребёнок называет родителя в собственном имени — **`NN_epicMM_<фаза>_<name>.md`**,
где `MM` — номер родительского эпика. Детализируется только ближайшая фаза; план фазы N+1 пишется на
закрытии фазы N. Работа, которой эпик не потребовался, остаётся **самостоятельным** планом:
`NN_<name>.md`. Конвенция действует вперёд — старые планы не переименовываются: их номера уже
процитированы по всей истории.
