# План 20 — Перебивание голосом: встроенный AEC + активаторы, устойчивые к речи

**Основание:** `bugs/25` (дефект), `researches/23` (разведка), `interviews/interview_009` (три
ответа владельца, все — вариант A).
**Цель одной строкой:** сказать «Джарвис» или «Джой», ПОКА ассистент говорит, — и он замолчит и
станет слушать.

## Критерии готовности (числа, а не впечатление)

Все проверяются `tools/voice/wake-bargein-probe.py` — стенд уже есть и уже доказал свою
повторяемость (`--selfcheck` 4/4).

- [ ] эхо в микрофоне подавлено **≥15 дБ** (сейчас пик 914–1276 ⇒ должно стать не выше ~160);
- [ ] на синтетике при SNR **+18 дБ** оба детектора дают **≥0.5**;
- [ ] контроль «только речь ассистента» остаётся **≤0.05** (ложных самоперебиваний не появилось);
- [ ] живой прогон владельца: перебивание срабатывает посреди речи (`homeworks/05`);
- [ ] бенч голосового тракта **35/35** не просел.

## Шаг 1. Помощник захвата с подавлением эха ✅ собран, не проверен

- [x] `tools/voice/aec-capture/aec_capture.cpp` — Voice Capture DSP (`CLSID_CWMAudioAEC`) в режиме
      **source**: система сама берёт микрофон и поток на колонки, отдаёт 16 кГц моно s16le в stdout.
      Тот же контракт, по которому слушатель читает ffmpeg ⇒ подмена drop-in.
- [x] Нелинейная обработка выключена намеренно (`researches/23` §1: активатор её не терпит):
      шумодав DSP, АРУ и центральный клиппер — off.
- [x] Ключи свойств и `SINGLE_CHANNEL_AEC = 0` взяты из заголовка SDK, GUID'ы — из `.lib` системы.
- [x] `--no-aec` как КОНТРОЛЬ: тот же тракт без подавления. Без него замер сравнивал бы две разные
      программы, а не работу подавителя.
- [x] Сборка: `tools/voice/aec-capture/build.ps1` (Build Tools 2022 есть, `cl` не в PATH — поднимаем
      через `vcvars64`).
- [ ] **Открыто:** какой индекс `--spk` соответствует колонкам, через которые реально играет
      ассистент. Имена `waveOut` обрезаны до 31 символа, надёжно сопоставить с endpoint по имени
      нельзя — спрошено у владельца.

## Риски

- **DSP старый и одноканальный** — если моно-выход окажется неприемлемым на слух, остаётся
  вариант B из `interview_009` Q1 (WebRTC APM в отдельном venv на 3.13).
- **Source mode может не открыть нужную пару устройств** — тогда filter mode, но это переделка
  воспроизведения (подача опорного сигнала), то есть заметно дороже.
- **Переобучение может не спасти Джой** — тогда честно сказать владельцу и обсудить более длинное
  имя или второй активатор.
