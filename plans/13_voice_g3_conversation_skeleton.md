# План 13 — Голосовой тракт Г3: «Скелет разговора» (микрофон → ядро → динамики)

> Фаза Г3 голосового блока. Зонтик — [plans/07](07_jarvis_gateway_and_client.md); предыдущие —
> [Г1 «Голос»](11_voice_g1_tts_silero.md), [Г2 «Уши»](12_voice_g2_stt_gigaam.md). Мозг —
> принятое ядро OpenClaw ([plans/10](10_openclaw_core_rollout.md), гейтвей в tailnet).
> Статус: 🟡 **каскад работает, но критерий латентности провален на новом движке.** Перезамер
> 2026-07-28 (b10167): тёплый ход **24.5–26.7 с** против 20–22 с — критерий <25 с больше не держится
> (см. шаг «Перезамер» ниже). Живой микрофон владельцем пройден, вердикт жёсткий: *«голоса уёбищные,
> всё медленно; TTS не произносит английские слова, STT пишет английское кириллицей»*. Из этого уже
> заведён `bugs/06` (реплика без русских букв роняла ход — крах устранён), остальное ждёт разноски.

## Цель

**Первый живой голосовой разговор с KLAS на самом ПК:** push-to-talk скрипт слушает микрофон,
распознаёт (Г2), отправляет текст в ядро OpenClaw, озвучивает ответ (Г1). Сквозная латентность
замерена. Без телефона, без wake word, без barge-in — скелет.

## Принцип (KISS)

БЕЗ Pipecat на этом шаге: прямой каскад в одном скрипте (`STT → openclaw agent → TTS`) — минимум
сущностей, максимум прозрачности. Pipecat (barge-in, turn detection, WebRTC) подключаем в Г4/Г5,
когда пойдёт realtime-стриминг на устройства — так каркас докажет необходимость (PHILOSOPHY).

## Шаги

- [x] **Каскад** `tools/voice-talk.mjs`: push-to-talk (Enter старт/стоп, запись ffmpeg dshow
      16 кГц, мик по умолчанию «Микрофон (NVIDIA Broadcast)», `--device` для смены) → Г2-STT →
      ход ядра (`openclaw agent --session-key voice-<дата>`, контекст в сессии) → Г1-TTS →
      динамики. Автономный режим `--wav <файл>` — прогон каскада без микрофона (харнесс).
- [x] **Латентность по этапам (замер 2026-07-17):** холодный ход 64 с (свап модели + первый ход
      сессии); **тёплый ход 20–22 с** (уши 1.5 · ядро ~7 · рот 4.2) — критерий <25 с ВЗЯТ.
- [x] **⚠️ ПЕРЕЗАМЕР на движке b10167 (2026-07-28) — критерий <25 с БОЛЬШЕ НЕ ДЕРЖИТСЯ.** Три тёплых
      хода подряд: **24.5 · 25.7 · 26.7 с** (уши 1.3–1.7 · ядро **10.1–10.8** · рот 4.4–5.3); холодный
      67 с. Регресс сидит в ядре: было ~7 с, стало ~10.4 с (+50%). Аудио-половины не изменились,
      round-trip «рот→уши» те же **97%** — то есть Г1/Г2 чисты, вопрос только к ходу ядра.
      **Атрибуция не завершена честно:** проверена и ОТВЕРГНУТА гипотеза «виноваты схемы Windows-MCP
      в промпте» (они дают 1.8k токенов из 20.5k: 20 560 против 18 760 с выключенным MCP). Остаются два
      подозреваемых, которые разделяются только A/B-прогоном на стенде: **смена билда** (b9538 → b10167)
      и **смена основной модели** (базу 07-17 мерили до перехода на `qwen3.6-35b-a3b`, интервью 006).
      Полезная деталь для оптимизации: в ходе 20 560 токенов промпта, из них 19 576 из KV-кеша, а
      выход — **4 токена**; значит секунды уходят НЕ на генерацию, и «меньшая модель» проблему не решит.
- [x] **Голосовой стиль:** префикс-инструкция в каждом ходе (константа `VOICE_STYLE`) — ответы
      короткие/разговорные, подтверждено тестом (правка IDENTITY.md не понадобилась — KISS).
- [x] **Контекст сессии:** «запомни: любимое число 42» → следующий ход «какое моё число?» → «42» ✓.
- [x] **Строка в харнесс-таблицу** `AGENT_GUIDE.md`.
- [ ] 🏠 **Живая микрофонная проверка владельцем:** `node tools/voice-talk.mjs` — сказать пару
      фраз push-to-talk; вписать сюда впечатление/дефекты (мик по умолчанию NVIDIA Broadcast).

## Проверка (критерий готовности)

✅ Автономный каскад: синтезированный вопрос → распознан → ядро ответило по-русски кратко →
ответ озвучен; 3 связных хода одной сессии; тайминги напечатаны. Остался живой микрофон (🏠).

## Риски

- **Латентность ядра** — риск РЕАЛИЗОВАЛСЯ: 10.1–10.8 с на ход (2026-07-28), владелец назвал тракт
  медленным. Пути ускорения в порядке ожидаемой отдачи: (1) **стриминг TTS по предложениям** — режет
  не время ядра, а ВОСПРИНИМАЕМУЮ задержку, и бьёт прямо в жалобу владельца; (2) разобраться с
  20-тысячным системным промптом (генерация тут ни при чём — выход 4 токена); (3) A/B билдов на стенде
  `llamacpp-probe`, чтобы понять цену обновления движка. «Меньшая модель для голосовых интентов»
  из списка ВЫЧЕРКНУТА замером: время уходит не на генерацию.
- **Ответ без русских букв роняет весь ход** (`bugs/06`) — крах устранён охранником, но числовые и
  английские ответы KLAS пока молчит; полное лечение (нормализация чисел + произношение латиницы)
  ждёт решения владельца, потому что упирается в его же жалобу на двуязычность.
- Запись микрофона в Node на Windows — если пакеты записи хрупкие, сайдкар: sherpa-onnx mic-пример
  или ffmpeg (dshow) как записыватель.
