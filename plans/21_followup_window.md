# План 21 — Окно продолжения: разговор без повторного имени

**Основание:** `ideas/19` (идея владельца, дословно) + прямое требование 2026-08-01:
*«после реплики джарвиса не было сигнала, приглашающего меня произвести фразу. Нужно чтобы оно
автоматически само запускало слушание и сигналом меня приглашало»*.
**Тип:** обычная задача (`/plan-task`), не эпик: одна фича, две подсистемы, обратимо.

## Цель одной строкой

Сказал имя один раз — дальше говоришь репликами, как с человеком; имя нужно только чтобы НАЧАТЬ
разговор или СМЕНИТЬ персону.

## Критерии готовности (проверяемые, не на ощупь)

- [ ] после ответа ассистента звучит приглашающий сигнал и открывается окно на `--wait` секунд;
- [ ] сказанное в окне уходит в ядро БЕЗ имени и той же персоне, что отвечала;
- [ ] промолчал — звучит нисходящий сигнал, дальше снова нужно имя;
- [ ] **приглашающий сигнал НЕ попадает в запись** (иначе повторится дефект, из-за которого
      владелец видел «(тишина — ничего не распознано)» вместо своих пяти секунд);
- [ ] имя ВНУТРИ окна работает — в том числе чужое, для смены персоны;
- [ ] перебивание не открывает окно (там уже говорит человек);
- [ ] самопроверка автомата конца фразы 6/6 и стенд отложенного захвата — зелёные;
- [ ] бенч голосового тракта 35/35 не просел;
- [ ] живая проверка владельцем.

## Шаги

- [x] **1. Протокол.** Команда `{"cmd":"followup","detector":"<slug>"}` взводит тот же захват, что и
      срабатывание детектора: ждём речь `--wait` с, пишем фразу, ловим конец тем же автоматом.
      Новой подсистемы нет — есть второй способ взвести существующую.
- [x] **2. Слушатель.** Захват из окна помечается `followup`; пустота из него значит «разговор
      окончен» (`reason: followup-timeout`), а не «сказали только имя». Захват заводится СРАЗУ
      взведённым (`pending`), потому что в этот момент играет приглашающий сигнал.
- [x] **3. Дирижёр.** После успешного хода: сигнал → команда окна. Перебитый ход окно НЕ открывает —
      там уже говорит человек, приглашение было бы ложью. Плюс печать вслух: «говори дальше без
      имени — <персона> слушает N с», потому что одного сигнала мало, человек должен видеть, сколько
      у него времени и с кем он продолжает.
- [x] **4. Цепочка ходов.** Реплика из окна идёт тем же путём, что и после имени, и по завершении
      снова открывает окно — разговор продолжается, пока человек говорит.
- [x] **5. Выключатель** `--no-followup`.
- [x] **6. Проверка стендами.** Фикстурой сквозь `voice-wake` это НЕ проверяется: пока ядро думает
      свои двадцать секунд, звуковой файл кончается, и окно открывается в пустоту. Поэтому проверка
      идёт стендом `wake-speaking-probe.mjs --followup`, где роль дирижёра играет скрипт:

      | случай | результат |
      |---|---|
      | человек заговорил (`--expect speech`) | окно открылось · **сигнал в запись не попал** · фраза захвачена БЕЗ имени · помечена `followup` |
      | промолчал (`--expect timeout`) | окно закрылось само · причина названа верно (`followup-timeout`) |

      ⚠️ Стенд сначала краснел на ИСПРАВНОМ поведении: он всегда ждал речь и считал молчание
      провалом. Исправлено флагом `--expect`: оба исхода правильные, и прибор обязан их различать —
      иначе он приучает игнорировать собственную красноту.

## Риски и как их ловим

| риск | почему правдоподобен | что делаем |
|---|---|---|
| **Сигнал попадает в запись** | уже случилось один раз в этой же сессии | захват взводится `pending`, ждёт тишины; проверяется стендом `wake-speaking-probe.mjs` |
| **Комната открывает ходы к ядру** (телевизор, разговор рядом) | окно слушает БЕЗ имени — порог входа исчез | уши вернут пустоту, дирижёр это переживает; если станет мешать — минимальная длительность речи |
| **Разговор не заканчивается** (окно за окном) | цикл замкнут по построению | окно открывается только после УСПЕШНОГО хода; промолчал — цикл рвётся |
| **Собственное эхо в окне** | AEC на этой машине не работает (`plans/20`) | окно открывается после конца речи, захват ждёт тишины |
| **Владельцу не понравится сам режим** | меняет привычку разговора | флаг `--no-followup` |
