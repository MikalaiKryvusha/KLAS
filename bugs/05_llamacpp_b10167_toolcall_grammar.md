# Bug 05 — llama.cpp b10167: грамматика тул-коллов ссылается на неопределённые правила → любой ход ядра падает 400

**Статус:** 🔬 исследован, обойдён откатом (движок возвращён на b9538); апстрим-тикет НЕ заведён
**Версия/сборка:** llama.cpp **b10167** (`ee3d1b54c`, релиз 2026-07-28, сборка win-cuda-13.3-x64) ·
рабочая сборка сейчас — **b9538** (`5343f4502`, 06.06.2026)
**Когда/контекст:** 2026-07-28, при обновлении движка ради фикса апстрим-issue #24807 (живой UI-тест,
`plans/16`)

## Симптом

После подмены движка на b10167 **любой** ход агентного ядра OpenClaw падает мгновенно (0.2–0.5 с):

```
400 Failed to initialize samplers: failed to parse grammar
```

Падает даже тривиальное «скажи привет» — без Windows-MCP, на всех трёх моделях цепочки
(`qwen3.6-35b-a3b` → `qwen3.6-35b-a3b-r` → `qwen3.5-35b`). При этом:

- одиночный тул-колл простой схемы через `curl`/`Invoke-RestMethod` — **работает идеально**
  (чистый JSON `tool_calls`, без XML-псевдоформата, ради чего обновление и затевалось);
- все 7 схем Windows-MCP, отправленные напрямую (нестримингом), — тоже **200 OK**.

То есть ломается именно полный набор схем, который шлёт ядро.

## Воспроизведение (детерминированное)

```powershell
# 1. поднять стенд на b10167 (отдельный порт, боевой стек не трогаем)
Start-Process F:\KLAS\llamacpp-b10167\llama-server.exe -WindowStyle Hidden -RedirectStandardError err.txt `
  -ArgumentList '-m','F:\KLAS\LLMs\LLAMACPP_MODELS\Qwen3.6-35B-A3B-UD-IQ3_S.gguf','--port','5900',
                '-c','98304','-ctk','q8_0','-ctv','q8_0','-ngl','99','--flash-attn','on','--jinja'
# 2. временно увести провайдера на стенд: models.providers.klas.baseUrl → http://127.0.0.1:5900/v1
# 3. один ход ядра
openclaw agent --local --session-key probe -m 'привет'      # → 400 failed to parse grammar
# 4. улика — в stderr САМОГО движка
Get-Content err.txt -Tail 60 | Select-String '::=|failed to parse grammar'
```

⚠️ `--chat-template-kwargs '{"enable_thinking": false}'` через PowerShell передавать нельзя — оболочка
калечит inline-JSON (`parse error … last read: '{e'`). Для воспроизведения флаг не нужен.

## Криминалистика

Движок печатает сгенерированную грамматику целиком; падение — на строках, которые **ссылаются на
правила, нигде не определённые**:

```
tool-windows-Type-arg-label ::= ("<parameter=" "label" ">\n") "" tool-windows-Type-arg-label-schema "\n</parameter>\n"
tool-windows-Type-arg-label-schema ::= integer | null          ← integer/null не определены
…
value ::= object | array | string | number | boolean | null    ← база JSON тоже не определена
E failed to parse grammar
E srv  send_error: task id = 0, error: Failed to initialize samplers: failed to parse grammar
E srv  process_sing: failed to launch slot with task, id_task = 0
```

Первое правило пришло из Windows-MCP (`label: int | None` в `input.py`), второе — из встроенных схем
самого OpenClaw (воспроизводится с `mcp.servers.windows.enabled = false`).

## Корневая причина / Гипотезы

**Гипотеза №1 (основная, подтверждена уликой):** в b10167 генератор GBNF для **XML-формата тул-коллов
Qwen3.6** (`TAG_WITH_TAGGED`, тот самый путь, который чинили в #24807) выпускает ссылки на базовые
JSON-правила (`object`, `array`, `string`, `number`, `boolean`, `null`, `integer`), но не эмитит их
определения. Любая схема со свободным или nullable значением → битая грамматика → 400 ещё до генерации.

Косвенно за: нестриминговые запросы с теми же схемами проходят (грамматика в этом пути, видимо, не
строится), а ядро шлёт стриминг с ленивым триггером грамматики — и падает всегда.

**Гипотеза №2 (не проверена):** дефект внесён где-то между b9754 (где #24807 подтверждённо починен) и
b10167. Проверяется бисекцией релизов на стенде — см. план фикса.

## Решения, принятые без владельца

1. **Откатил движок, не дожидаясь разбора.** Выбор между «чинить на живом стеке» и «вернуть рабочее» —
   решил по канону «стабильность выше всего» (`GOAL.md`): ассистент лежал полностью.
2. **Оставил папку `llamacpp-b10167` на диске** (0.7 ГБ) вместо удаления — она нужна для бисекции и
   стендовых опытов. Если владелец против — удалить одной командой.
3. **Тикет в апстрим НЕ заводил** — публикация вовне требует слова владельца.
4. **Стенд поднимал без `--chat-template-kwargs`** (PowerShell калечит JSON-аргумент). Для грамматики
   тул-коллов флаг нерелевантен, но замер «холодного» поведения модели с ним не сравнивался.
