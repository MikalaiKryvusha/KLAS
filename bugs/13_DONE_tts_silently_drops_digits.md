# Bug 13 — РОТ молча ГЛОТАЕТ цифры: «Температура 20 градусов» звучит как «температура градусов»

**Статус:** ✅ DONE (2026-07-29) — фикс применён для ОБОИХ языков, охранник проверен на сломанной версии
**Версия/сборка:** `tools/voice/silero_daemon.py`, Silero **v5_ru**, голос `eugene`
**Когда/контекст:** 2026-07-29, при построении детерминированной проверки нормализации (следующий
шаг из `bugs/12`)

## Симптом

Любое число, стоящее в предложении РЯДОМ С БУКВАМИ, не произносится вообще. Ассистент говорит фразу
без него, не запинаясь и без единой ошибки в логах.

| синтезировали | уши KLAS слышат |
|---|---|
| `115 килобайт в секунду` | `килобайт в секунду` |
| `42 плюс 14 будет 56.` | `плюс будет` |
| `Диск на 2 ТБ и 500 ГБ.` | `диск на терабайты гигабайт` |
| `Температура 20 C, влажность 60%.` | `температура градусов цельсия влажность процентов` |

## Криминалистика — доказано ДЛИТЕЛЬНОСТЬЮ, а не выводом ушей

Уши GigaAM физически не умеют печатать цифры (34 токена, только кириллица), поэтому по одному их
выводу обвинять рот НЕЛЬЗЯ — это была бы та же ошибка, что в `bugs/08`. Решающая улика — длительность:

| текст | длительность звука |
|---|---|
| `115 килобайт в секунду` | **1.09 с** |
| `килобайт в секунду` (числа нет вовсе) | **1.09 с** ← в точности столько же |
| `сто пятнадцать килобайт в секунду` | 1.74 с |
| `Температура 20 градусов.` | **1.34 с** |
| `Температура градусов.` | **1.34 с** ← в точности столько же |
| `Температура двадцать градусов.` | 1.70 с |

Число даёт **ноль звука**. Silero v5_ru выбрасывает цифровые токены.

## Корневая причина

В `synth_segments` разворот цифр в слова применялся **только к отрезкам БЕЗ БУКВ**:

```python
if lang is None:
    if not DIGIT.search(chunk): continue
    chunk, lang = digits_to_words(chunk), "ru"   # ← только здесь
```

Логика писалась под `bugs/06`, где задача формулировалась как «реплика без русских букв роняет
синтез». Настоящая причина оказалась шире: Silero не читает цифры **нигде**, просто на безбуквенном
тексте это давало падение (заметно), а в обычном предложении — тихое выпадение слова (незаметно).

**Почему не поймали раньше — три слоя маскировки:**
1. `VOICE_STYLE` просит МОДЕЛЬ писать числа словами, и она обычно слушается ⇒ цифр в тексте чаще нет;
2. детерминированная подстраховка срабатывала только на безбуквенном тексте;
3. **порог бенча `WORD_MATCH_MIN = 0.6` прятал остаток:** во фразе «115 килобайт в секунду» пропажа
   одного токена из четырёх даёт 0.75 — выше порога, проверка зелёная. Отсюда и наблюдавшиеся
   в прогонах 0.87/0.90 вместо 1.00.

## ✅ Фикс (применён для ОБОИХ языков)

Разворот цифр в слова применяется к **ЛЮБОМУ отрезку**, а не только к безбуквенному:

```python
chunk = digits_to_words(chunk) if lang == "ru" else digits_to_en_words(chunk)
```

**Английская модель глотает цифры ровно так же** — проверено тем же методом длительности:

| текст | было |
|---|---|
| `It costs 115 dollars.` | **1.19 с** |
| `It costs dollars.` (числа нет) | **1.19 с** ← столько же |
| `It costs one hundred fifteen dollars.` | 2.20 с |

Поэтому добавлен `number_to_en_words` / `digits_to_en_words` — маленький разворот английских
числительных без зависимостей (русские слова в латинском отрезке звучали бы дико).

## ✅ Проверка наблюдением (окружение владельца)

| вход | `spoken` после фикса | уши KLAS |
|---|---|---|
| `115 кб/с` | сто пятнадцать килобайт в секунду | «сто пятнадцать килобайт в секунду» ✅ |
| `42 плюс 14 будет 56.` | сорок два плюс четырнадцать будет пятьдесят шесть. | ✅ полностью |
| `Температура 20 C, влажность 60%.` | двадцать градусов Цельсия … шестьдесят процентов | ✅ полностью |
| `Сейчас 2026 год.` | Сейчас две тысячи двадцать шесть год. | ✅ |
| `Скорость 115 кб/с в тесте machine learning.` | … + английский термин сохранён | ✅ смесь работает |
| `The model has 7 billion parameters.` | The model has seven billion parameters. | 2.24 с = версия словами ✅ |

Длительности подтверждают: `115 килобайт в секунду` 1.09 → **1.74 с** (ровно как у версии словами).

## Охранник — T0b в `tools/voice-bench.mjs`

Детерминированная проверка нормализации сразу после старта рта: фикстура из 6 строк (включая
английскую), инвариант — **в произнесённом тексте не должно остаться НИ ОДНОЙ цифры**. Инвариант
выбран нарочно простой: он не зависит от формулировок и ловит весь класс.
**Проверен на сломанной версии:** с выключенным разворотом — `❌ FAIL 0/6` с перечислением всех
шести строк; с фиксом — `✅ PASS 6/6`.

## ⚠️ Известные границы (не чинено, осознанно)

- **Согласование падежей:** «два терабайт» (правильно «два терабайта»), «две тысячи двадцать шесть
  год» (правильно «шестой год»). Полное согласование требует морфологии — новая зависимость ради
  косметики; сейчас число ЗВУЧИТ, и это главное.
- **Дробные числа:** `3.14` разворачивается как два целых («три … четырнадцать»). Редкий случай в
  разговорной реплике; отмечено, чтобы следующая сессия не считала это сюрпризом.

## Влияние на владельца

Прямое и постоянное: ассистент, который называет время, температуру, размеры, цены и результаты
вычислений, **произносит все эти фразы без чисел**. Для голосового помощника это дефект первого ряда.

## Решения, принятые без владельца

1. **Разворот цифр включён БЕЗУСЛОВНО, а не по флагу.** Альтернатива — оставить выбор владельцу.
   Отвергнута: «не произносить числа» не может быть желаемым поведением ассистента, а лишний флаг —
   лишняя сущность.
2. **Английские числительные написаны свои (~40 строк), а не взяты библиотекой** (`num2words` и т.п.).
   Причина — правило «минимум сущностей»: новая зависимость в venv ради того, что укладывается в
   таблицу из трёх списков, не окупается.
3. **Согласование падежей НЕ делаю** (см. границы выше): это морфология, то есть новая зависимость,
   ради косметики. Число теперь звучит — дефект закрыт; красота склонения — отдельная задача, если
   владелец её захочет.
4. **Формулировка в `bugs/06` не переписана задним числом.** Там сказано «числа произносятся
   словами»; это было верно ДЛЯ ЕГО СЛУЧАЯ (текст без букв). Вместо правки старого документа
   поставлена ссылка отсюда — история диагнозов не переписывается.
