# Bug 06 — голосовой ход умирает, когда ответ ядра без русских букв («56.», «OK.»)

**Статус:** ✅ **DONE (2026-07-29)** — вылечено полностью: числа произносятся словами, английский —
собственной моделью. Молчания больше нет. Развилка «как читать латиницу» решена ВЛАДЕЛЬЦЕМ (см. ниже),
поэтому интервью не понадобилось.
**Компонент:** «РОТ» (Г1) — Silero v5 ru через `tools/voice-say.mjs` → `tools/voice/silero_say.py`
**Когда/контекст:** найден 2026-07-28 при перепроверке голосового тракта на новом движке b10167
(`plans/16`, хвост смены билда). Движок к дефекту отношения не имеет — он был всё это время.

## Симптом

Живой голосовой ход: вопрос «сколько будет семь умножить на восемь» → ядро отвечает `56.` → **весь
процесс `voice-talk` падает стеком**, ответ не озвучен, диалог оборван:

```
🎤 Ты: сколько будет семь умножить на восемь
🤖 KLAS: 56.
Error: РОТ упал: prepare_tts_model_input
    clean_text_list = self.process_simple_text(text)
  File "<torch_package_0>.multi_acc_v3_package.py", line 223, in process_simple_text
    raise ValueError
```

## Корневая причина (ПОДТВЕРЖДЕНА наблюдением)

Препроцессор Silero v5 ru (`process_simple_text`) требует в тексте **хотя бы одну кириллическую
букву**. Без неё он кидает голый `ValueError` (без сообщения). Проверено перебором:

| Текст | Результат |
|-------|-----------|
| `56` | ❌ ValueError |
| `56.` | ❌ ValueError |
| `OK.` | ❌ ValueError |
| `Ответ: 56.` | ✅ синтез |
| `42 плюс 14.` | ✅ синтез |
| `Минск.` | ✅ синтез |

То есть **цифры и латиница сами по себе не озвучиваются, а вместе с кириллицей — озвучиваются**.
Дефект не в цифрах как таковых, а в отсутствии русских букв во ВСЕЙ реплике.

Почему не поймали раньше: автономный `voice-roundtrip` гоняет 10 заготовленных РУССКИХ фраз, а живые
прогоны Г3 задавали вопросы, на которые ядро отвечало предложениями. Короткий фактический ответ
(«56.», «OK.», «Windows 11») в тесты не попадал ни разу — классическая дыра фикстуры.

## Лечение

### Применено (2026-07-28) — крах убран

1. **Охранник в `tools/voice-say.mjs`**: если в тексте нет кириллицы — не звать сайдкар, напечатать
   внятную причину и выйти **кодом 2** (отдельный код = «нечего произносить», не «РОТ сломан»).
2. **`tools/voice-talk.mjs` переживает этот случай**: `say()` возвращает `false`, ход печатает
   `(не озвучено: в ответе нет русских букв — bugs/06)`, тайминги и диалог продолжаются.

Проверено тем же прогоном, который падал: `node tools/voice-talk.mjs --wav ... ` → ядро снова ответило
`56.`, ход завершился штатно (`exit=0`), стека нет. [TESTED: 2026-07-28 · живой прогон каскада]

### Применено (2026-07-29) — молчание убрано, развилка закрыта СЛОВОМ ВЛАДЕЛЬЦА

Развилка «как читать латиницу» была отправлена в `/interview`, но владелец ответил прямо в чат
(2026-07-29): *«почини его произношение английского текста. Для меня важно, чтобы он в одной реплике
умел быстро переходить с русского на английский, как живой человек в живой беседе. Если ответ LLM —
смесь языков, это должно звучать корректно»*. Вариант выбран — **настоящая английская фонетика**, а не
транслитерация. Реализация:

1. **Двуязычный резидент** `tools/voice/silero_daemon.py`: текст режется по алфавиту, русские отрезки
   синтезирует `v5_ru`, английские — `v3_en` (английских v4/v5 у Silero нет, проверено запросом
   2026-07-28), куски склеиваются в одну дорожку с паузой 60 мс на стыке. Английская модель грузится
   лениво — при первой латинице, чтобы не удлинять старт русского диалога.
2. **Числа → слова** для текста БЕЗ букв (`56` → «пятьдесят шесть») — собственный `number_to_ru_words`
   с русскими формами разрядов. В остальных случаях цифры читает сам Silero, он это умеет.
3. **Единицы измерения словами** (требование владельца 2026-07-29: «115 кб/c» на слух непонятно):
   детерминированный разворот в резиденте + инструкция модели в `VOICE_STYLE`. Разворачивается только
   то, что стоит ПОСЛЕ ЧИСЛА, — поэтому `C++` и `C#` не трогаются (проверено).
4. **Markdown вычищается** перед синтезом — у `**` нет звучания, а модель их иногда просачивает.

**Проверено наблюдением, а не чтением диффа:** `node tools/voice-bench.mjs` — 35/35, включая случаи
«число» (`56` → услышано «пятьдесят шесть»), «латиница» (`cat`), «смесь языков» («Эта технология
называется machine learning» — `langs: [ru, en]`) и «единицы». Каждый случай судится распознаванием
звука ушами GigaAM, а не тем, что файл создался.

⚠️ **Честная граница:** КАЧЕСТВО английского произношения бенчем не проверяется — уши KLAS
(GigaAM) понимают только русский, английские куски они не распознают. Судить английский может
пока только человек.

## Радиус поражения

`tools/voice-say.mjs` (охранник) · `tools/voice-talk.mjs` (устойчивость хода) · планы `11` (Г1) и
`13` (Г3). Тот же охранник защищает и TTS-провайдера ядра OpenClaw (`tts-local-cli` → `voice-say.mjs`,
`plans/14`): там падение сайдкара точно так же роняло бы ход ноды.

## Решения, принятые без владельца

- **Код выхода 2 вместо нового флага** — минимум сущностей: вызывающему нужно отличить «нечего
  произносить» от поломки, и кода выхода для этого достаточно.
- **Проверка на кириллицу, а не на «есть ли буквы вообще»** — потому что перебор показал: латиница
  БЕЗ кириллицы тоже падает, значит критерий именно «есть русская буква».
- **Не стал делать нормализацию чисел явочным порядком** (28.07), хотя она бесспорна: она неразрывна с
  вопросом латиницы, а он владельческий. Разводить их в разные релизы — плодить полумеры.
- **Два слоя лечения единиц вместо одного** (29.07): инструкция модели И детерминированный разворот в
  резиденте. Одной инструкции локальной модели верить нельзя — она её забывает; один разворот без
  инструкции чинит только известные сокращения. Цена — дублирование смысла в двух местах, и она
  названа в комментариях обоих файлов.
- **Разворот единиц срабатывает только после числа.** Иначе «в» и «с» из обычного текста уезжали бы в
  единицы. Цена: «м/с» без числа перед ним не развернётся. Выбрано «лучше не тронуть, чем произнести
  неверно».
- **Английский голос — `en_0` по умолчанию** (v3_en даёт en_0…en_117). Выбран первый как нейтральный;
  подбор английского голоса под персону — задача Г5 (`plans/15`), вместе с клонами.
- **Список единиц намеренно короткий** (два десятка позиций) и расширяемый: выдумывать полный словарь
  сокращений заранее — плодить сущности; добавляем по мере встреч.
