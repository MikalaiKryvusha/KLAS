# Bug 23 — «анонимная установка» в мастере ничего не обезличивает (вызов без --apply)

**Статус:** ✅ ПОЧИНЕНО (2026-08-01). Найден 2026-07-31 при перевыводе README из кода (ревизия фактов).
**Где:** `tools/install.mjs` (вызов анонимизации) против `tools/anonymize.mjs` (контракт флагов).
**Охранник класса:** `tools/dry-run-guard.mjs` (`npm run guard:dry-run`).

## Симптом

Пользователь отвечает мастеру «Ставить анонимно? — да», установка завершается экраном успеха —
а копия остаётся полностью НЕобезличенной: имена, ссылки и origin автора на месте.

## Причина (подтверждена чтением кода)

- `tools/install.mjs:229` при `answers.anonymous` вызывает `node tools/anonymize.mjs` **без
  флага `--apply`**;
- `tools/anonymize.mjs:22`: `const APPLY = process.argv.includes('--apply')` — без флага скрипт
  работает в режиме DRY-RUN: печатает план и не меняет ни одного файла.

Мастер честно показывает вывод dry-run в консоли, но не читает его смысла: для мастера exit 0 =
«анонимизировано». Это тот же класс, что `bugs/21` (экран успеха после провала шага): гейт есть,
но проверяет не то.

## Класс

Инструмент, который вежливо репетирует вместо того, чтобы делать, + вызывающая сторона, которая
не отличает репетицию от исполнения. Смежные грабли: `bugs/21`, EXP-0042 («бумажный охранник»).

## Воспроизведение (детерминированное, без человека и без скачивания гигабайтов)

Мастер невозможно прогнать «как есть» — он качает гигабайты, поднимает боевой стек и трогает
Рабочий стол. Поэтому проверка идёт на ОДНОРАЗОВОМ КЛОНЕ с четырьмя заглушками; ответы мастера
подаются заранее, через файл состояния:

```powershell
git clone F:\KLAS <песочница>
node <скрипт подготовки> <песочница>        # заглушки: deploy.mjs, klas.ps1, health-check.ps1,
                                            #   install-desktop-shortcuts.ps1 + .deploy-state.json
cd <песочница>
node tools/install.mjs --yes --lang ru
```

⚠️ **Файл состояния писать БЕЗ BOM.** Первый прогон провалился не на баге, а на моей же ошибке:
`Set-Content -Encoding utf8` в PowerShell 5.1 добавляет BOM, `JSON.parse` на нём бросает, а
`loadState` глушит исключение и молча возвращает дефолт (`anonymous: false`) — ветка обезличивания
даже не запускалась, и прогон выглядел «чистым». Класс `AGENT_GUIDE.md` §9 (текст и кодировки).

Приём «ответы мастера через `.deploy-state.json`» работает потому, что `install.mjs:108` под
`--yes` разворачивает сохранённые ответы ПОСЛЕ дефолтов: `{ anonymous: false, …, ...state.answers }`.

## Фикс (одним коммитом)

1. **`install.mjs`** — вызов с `--apply` (без `--reinit-git`: стирание истории git необратимо и
   требует отдельного явного согласия пользователя).
2. **Судим по результату, а не по факту запуска.** `anonymize.mjs` сам грепает дерево на остатки
   личности (`PROBES`) и выходит кодом 1 при утечках ⇒ мастер останавливается ДО экрана успеха и
   печатает честный отказ (новый ключ `anonymize_failed` в обоих языках `tools/lib/i18n.mjs`).
3. **Охранник на класс** — `tools/dry-run-guard.mjs`: находит инструменты с контрактом
   «по умолчанию dry-run» ПО ИХ ИСХОДНИКАМ и красит любой их вызов из кода без `--apply`.
   Намеренная репетиция объявляется маркером `DRY-RUN-OK` рядом с вызовом.

## TWINS — искал класс по всему проекту

`TWINS: искал вызовы инструментов с контрактом «--apply» из исполняемого кода — найдено 2 вызова
(install.mjs:205 deploy.mjs — флаг был; install.mjs:229 anonymize.mjs — флага не было). Других
экземпляров класса нет; проверено машинно, а не глазами: tools/dry-run-guard.mjs, 43 файла.`

Рядом лежат, но это ДРУГИЕ классы — перечисляю, не чиню:

- `install.mjs` роняет коды возврата ярлыков, автозапуска, `klas.ps1 up` и `health-check.ps1`
  (строки 234/239/244/245). Из них значим последний: с `bugs/21` health-check умеет возвращать 1,
  а мастер этого не читает и рисует экран успеха со ссылками на возможно мёртвый стек. Не чинил
  вместе с этим багом: неизвестно, отвечает ли llama-swap на `/health`, когда модель ещё не
  загружена, — сделать провал фатальным без этого замера значит рискнуть ложной тревогой на
  исправной установке. Нужен отдельный замер и отдельный документ.
- Сообщение о провале деплоя (`install.mjs:211`) написано по-русски мимо словаря `i18n` —
  англоязычный пользователь получит русский текст. Косметика, другой класс (мультиязычие).

## Решения, принятые без владельца

1. **Провал обезличивания останавливает мастера** (а не «предупредить и идти дальше»). Выбирал по
   `bugs/21`: экран успеха над провалившимся шагом — тот самый дефект, который там лечили. Копия с
   чужим именем внутри опаснее незавершённой установки; состояние сохраняется, повторный запуск
   продолжает.
2. **`--reinit-git` не передаю.** Стирание истории git необратимо; в `bugs/23` это уже было
   записано как условие, оставил дословно.
3. **Мастер по-прежнему выходит кодом 0 при остановке** (`return`, а не `process.exit(1)`) — ровно
   как на провале деплоя из `bugs/21`. Менять код выхода мастера — отдельное решение, здесь не делал.
4. **Новый ключ `anonymize_failed` добавлен в оба языка**, а соседнее русскоязычное сообщение о
   провале деплоя не трогал (см. TWINS): копировать известный дефект в новый код нельзя, а чинить
   чужой — уже другая задача.
5. **Охранник не сканирует `package.json` и документацию.** В скриптах npm намерение объявлено
   именем (`deploy` против `deploy:apply`), а в README `node tools/deploy.mjs` — инструкция
   человеку, а не вызов. Сканировать их значило бы получать красное на законном.

## Что фикс сделал видимым

Пока анонимизация была репетицией, её собственная слепота не проявлялась. Теперь она реально
исполняется — и стало видно, что четыре файла с именем автора она не покрывает, а её валидатор
смотрит ровно туда же, куда скраббер, и поэтому рапортует «анонимность достигнута». Заведено
отдельным документом: **`bugs/24`**. Вопрос уровня владельца (обезличивать ли строку копирайта в
`LICENSE`, когда MIT требует сохранять уведомление) — в `interviews/interview_008`.
