# Bug 05 — «движок ломает грамматику тул-коллов»: на деле наша схема тула просила 65536 повторений

**Статус:** ✅ ЗАКРЫТ 2026-07-28 — корневая причина найдена и устранена на НАШЕЙ стороне; движок
обновлён до **b10167** и работает в бою
**Версия/сборка:** был b9538 (`5343f4502`, 06.06.2026) → стал **b10167** (`ee3d1b54c`, 28.07.2026,
win-cuda-13.3-x64). Откат — папка `F:\KLAS\llamacpp-b9538`
**Когда/контекст:** заведён 2026-07-28 при обновлении движка ради апстрим-фикса #24807 (живой UI-тест,
`plans/16`); закрыт в тот же день бисекцией, которая бисекции не потребовала

## Симптом

После подмены движка на b10167 **любой** ход агентного ядра OpenClaw падал мгновенно (0.2–0.5 с):

```
400 Failed to initialize samplers: failed to parse grammar
```

Падало даже «скажи привет» — без Windows-MCP, на всех трёх моделях цепочки. При этом одиночный
тул-колл через `curl` работал идеально, и схемы Windows-MCP по одной проходили 200 OK.

## Корневая причина (ПОДТВЕРЖДЕНА)

**Виноват не движок, а схема нашего инструмента.** Встроенный тул OpenClaw **`cron`** объявляет поле
`trigger.script` как строку с `maxLength: 65536`. Генератор GBNF разворачивает ограничение длины в
повторение символов, и в грамматике появляется:

```
tool-cron-arg-job-schema-trigger-script    ::= "\"" char{1,65536} "\""
tool-cron-arg-patch-schema-trigger-0-script ::= "\"" char{1,65536} "\""
```

А парсер грамматики llama.cpp имеет предохранитель (`src/llama-grammar.cpp`):

```c
#define MAX_REPETITION_THRESHOLD 2000
...
if (min_times > MAX_REPETITION_THRESHOLD || (has_max && max_times > MAX_REPETITION_THRESHOLD)) {
    throw std::runtime_error("number of repetitions exceeds sane defaults, please reduce the number of repetitions");
}
```

65536 > 2000 → грамматика не парсится → 400 **на каждом** запросе, ещё до генерации. Windows-MCP тут
ни при чём: `cron` — встроенный тул ядра, поэтому симптом воспроизводился и с выключенным MCP.

Почему это вылезло только после обновления: билд b9538 старше апстрим-фикса
[#24807](https://github.com/ggml-org/llama.cpp/issues/24807) и **не строил** грамматику для
XML-формата тул-коллов Qwen3.6 — до предохранителя дело просто не доходило (зато и тул-коллы `Type`/
`Click` не парсились, что и было исходным блокером `plans/16`). Билды после фикса грамматику строят —
и наша схема немедленно упирается в порог.

> ❌ **Ошибочная гипотеза первой редакции этого документа** (оставлена намеренно, как урок): «генератор
> GBNF ссылается на неопределённые правила (`value ::= object | array | …`)». Улику прочитали с
> середины дампа. На самом деле дамп ПОЛОН: 3617 правил, **ноль** неопределённых ссылок (проверено
> машинным разбором), а настоящая причина напечатана движком в ПЕРВОЙ строке над дампом —
> `parse: error parsing grammar: number of repetitions exceeds sane defaults`. Урок: читай сообщение
> об ошибке С НАЧАЛА вывода, а не с того места, где взгляд зацепился за знакомое.

## Лечение (применено)

**Одна строка в конфиге ядра** — штатный механизм OpenClaw, которым он же гасит такие же схемы у
моделей xAI (`XAI_UNSUPPORTED_SCHEMA_KEYWORDS`): вырезать из схем инструментов ключи, порождающие
повторения. У каждой модели провайдера `klas`:

```json
"compat": { "unsupportedToolSchemaKeywords": ["pattern", "maxLength", "minLength", "maxItems", "minItems"] }
```

Правка внесена и в рабочий `~/.openclaw/openclaw.json`, и в git-шаблон `openclaw/openclaw.json.example`.
Цена: модель перестаёт видеть подсказки о длине аргументов (валидацию это не отменяет — она на стороне
тула). Выгода: ядро снова делает ходы, и **любой** будущий тул с длинной строкой не уронит стек.

Стенд — `node tools/llamacpp-probe.mjs <билд>` (порт 5900, боевой стек не трогается):

| b9760 (первый после порога фикса) | ❌ 400 grammar → ✅ **PASS** после фикса схем | не гонялся (взят свежий билд) |
| **b10167 (принят в бой)** | ✅ **PASS** (30.8 с, `stopReason=stop`) | ✅ **PASS** — Блокнот открыт, `Click` отработал, `Type` напечатал текст |

Критерий (б) подтверждён не самоотчётом модели, а **записью экрана**: `tools/screen-rec.mjs` (1 кадр/с)

Боевая проверка после подмены папок: `health-check` зелёный (llama-swap, 6 моделей, VRAM),
`llama-server --version` = `10167 (ee3d1b54c)`, ход ядра через боевой 8080 — отвечает.

## Хвосты (вынесены отдельно, к этому багу не относятся)

1. **Новый Блокнот Windows 11 не отдаёт область ввода в UIA** — метки для неё нет вообще, поэтому
   `Type` по `label` невозможен; работает второй путь тула — `loc` (координаты). Канонический текст
   теста в `plans/16` фаза 4 поправлен.
2. ~~**Подмена символа при вводе:** запрошено `KLAS UIA test`, на экране `KLAS IIA test`.~~
   ❌ **Ложная тревога — дефекта нет.** Владелец посмотрел на экран: там `KLAS UIA test`, всё верно.
   Ошиблось МОЁ ЗРЕНИЕ: кадр записи ужимался с 6400 px до 1920, а просмотрщик агента ужимал ещё раз —
   на таком масштабе `U` вырождается в `I`. Инструмент исправлен (нативный масштаб по умолчанию +
   `--crop` для чтения текста), урок — `EXPERIENCE.md` EXP-0010. Оставлено в документе намеренно:
   зафиксированный ложный дефект дороже стёртого — он объясняет, почему у зрения теперь есть правило.

## Двойники

`TWINS: искал класс «наша схема/конфиг ломает чужой компонент, а виноватым назначен компонент» —
в проекте это УЖЕ второй случай: первым был compat-ключ "pattern" (llama.cpp 400 на схемах
инструментов, 2026-07-16), лечение там ровно то же. Значит класс не разовый: любой апгрейд движка
надо проверять ходом ядра, а первым подозреваемым держать НАШИ схемы. Вынесено в EXPERIENCE (EXP-0009).`

## Решения, принятые без владельца

1. **Взял самый свежий билд b10167, а не «максимальный работающий из бисекции».** После снятия
   истинной причины бисекция потеряла смысл: у нижней (b9760) и верхней (b10167) границ поведение
   одинаковое, а свежий билд несёт больше апстрим-фиксов. Откат лежит папкой `llamacpp-b9538`.
2. **Вырезал 5 ключей схем, а не только `maxLength`.** Соседи (`minLength`, `maxItems`, `minItems`)
   порождают повторения тем же механизмом; вырезать их сразу дешевле, чем ловить следующий тул.
   Это в точности набор, которым сам OpenClaw лечит модели xAI.
3. **Не стал отключать тул `cron`** (альтернативное лечение) — оно отняло бы функциональность и не
   защитило бы от следующей схемы с длинной строкой.
4. **Апстрим-тикет по-прежнему НЕ заведён.** Строго говоря, дефекта llama.cpp здесь нет: порог
   повторений — сознательный предохранитель. Кандидат на тикет в OpenClaw (генерировать схемы,
   переносимые для GBNF-грамматик) — только по слову владельца, публикация вовне.
5. **Стенд оставлен на диске** (`llamacpp-probe/`, в `.gitignore`) — переиспользуется при следующем
   обновлении движка.
