# Bug 20 — РЕВИЗИЯ 2026-07-31, часть 2: обвязка процессов и потоков (тихие потери и крахи)

**Статус:** ✅ ПОЧИНЕНО (2026-07-31, коммит `d815684`), синтаксис проверен; живой прогон SSE —
при следующем голосовом сеансе (помечено `[NOT-TESTED]` в коде)
**Где:** `tools/voice/pipeline.mjs`, `tools/gateway-churn-probe.mjs`, `tools/voice/tts-daemon.mjs`,
`tools/voice/single-instance.mjs`, `tools/voice-talk.mjs`, `tools/voice-bench.mjs`,
`tools/voice/silero_say.py`, `tools/voice/silero_daemon.py`, `tools/voice/normalize-loudness.mjs`,
`tools/voice/f0-of-wav.py`, `tools/voice/corpus-synth.py`

## 1. SSE-парсер терял строки, разрезанные границей чанка (боевой путь речи)

`pipeline.mjs` (и копия в `gateway-churn-probe.mjs`) разбирал КАЖДЫЙ чанк отдельно:
`decoder.decode(chunk).split('\n')`. Строка `data: {...}`, разрезанная сетью пополам, терялась
молча: первая половина — битый JSON в `catch { continue }`, вторая не начинается с `data: `.
`TextDecoder(stream:true)` чинит только разрезанные БАЙТЫ utf-8, не строки. Последствия: дыра
в речи (владелец слышит фразу без куска) или потерянный `finish_reason` → ложный красный T1
охранника `bugs/12` на исправном ходе. Лечение — буфер-перенос хвоста между чанками (общий
приём: `lines.pop()` в остаток). Дополнительно: обрыв стрима (смерть гейтвея, `bugs/15`)
оставлял `playChain` плавающим промисом — уже поставленные фразы доигрывали В ФОНЕ поверх
следующего кейса; теперь при исключении стрима очередь дожидается под присмотром.

## 2. `spawn` без обработчика `'error'` — крах вместо диагноза

Node: если процесс НЕ ЗАПУСТИЛСЯ (нет venv, нет ffmpeg в PATH), эмитится `'error'`, а не
`'exit'`; без слушателя это `Unhandled 'error' event` и смерть вызывающего с сырым стеком.
Закрыто в трёх местах: `tts-daemon` (теперь честный `stage:'dead'` + освобождение ожидающих),
`voice-talk` (микрофон), `voice-bench` (микрофон акустической петли). Смежное: подписка на
`'close'` ПОСЛЕ остановки ffmpeg ждала уже отстрелившее событие навсегда (мёртвый/занятый
микрофон = вечное зависание с занятым замком динамиков) — промис `closed` теперь создаётся
ДО остановки; stderr ffmpeg читается и печатается (раньше причина отказа устройства была
невидима); «Пустая реплика — выхожу» больше не маскирует отказ записи под намерение человека.

## 3. Замок динамиков: TOCTOU и чужой замок

`single-instance.mjs` захватывал через `existsSync` → `writeFileSync`: две сессии, стартующие
одновременно (ровно сценарий каши 2026-07-28, ради которого замок написан), проходили проверку
до чьей-либо записи — обе «захватывали». `release()` не проверял владение: сессия, чей замок
перезаписан, на выходе сносила ЧУЖОЙ. На свежей машине захват падал ENOENT (нет `voice/out`).
Лечение: `mkdirSync` + атомарный `{flag:'wx'}` + разбор EEXIST + release только своего pid.

## 4. Оборванные закачки моделей оставляли вечный битый файл

`silero_daemon.ensure_en_model` качал `urlretrieve` сразу в конечное имя: обрыв (рвущийся VPN —
известное состояние канала) оставлял частичный `v3_en.pt`, который `exists()` вечно принимал
за модель — каждый запуск падал на распаковке, самолечения не было. У `silero_say.ensure_model`
`unlink` в `except` не покрывал убитый процесс. Лечение обоим: закачка во временное имя +
`rename` после успеха. (Тот же паттерн `.part`+rename уже был в `deploy.mjs` — см. `bugs/21`
про его собственную граблю с 416.)

## 5. Мелкие тихие отказы того же класса

- `normalize-loudness`: JSON брался ПЕРВОЙ парой скобок из всего stderr (а первый проход идёт
  без `-loglevel error` — перед JSON дамп метаданных; `{` в ID3-теге ломала парс); код выхода
  был всегда 0 даже при «выровнено 0 из N». Теперь: последняя пара + честный exit.
- `f0-of-wav`: любой не-16-битный wav мерился как int16-шум → правдоподобный ложный F0, по
  которому сортировался кастинг. Теперь честный отказ с командой конвертации.
- `corpus-synth`: metadata.csv писался одним куском в конце — краш на 2900-й фразе из 3000
  терял ВСЕ метаданные при готовых wav. Теперь построчно с flush. Плюс контракт выхода
  приведён к фактическому входу `train_piper.py` (`wav/`, `имя.wav|текст`, 2 колонки) — прежняя
  «раскладка LJSpeech» обучателем не читалась вовсе (разъезд двух звеньев ОДНОГО конвейера).
- `gateway-churn-probe`: Ctrl+C оставлял N−1 вечных CPU-грелок сиротами (дефолтный SIGINT не
  зовёт хуки 'exit') — добавлен обработчик SIGINT; SSE-копия получила тот же буфер-перенос.
- `wakeword-probe`: off-by-one `range(0, len-1280, 1280)` всегда выбрасывал последний кадр
  80 мс, клип короче кадра не подавался вовсе. Вердикт «0/10» ОСТАЁТСЯ В СИЛЕ — положительный
  контроль «Alexa.» зажигался тем же циклом (EXP-0027), но прибор занижал score словам в конце
  записи. Теперь хвост добивается нулями до кратности кадра.

## Чем проверено

`node --check` всех файлов чист; `py_compile` чист; SSE-фикс помечен `[NOT-TESTED]` до живого

line-buffering, применён одинаково в обоих местах.
