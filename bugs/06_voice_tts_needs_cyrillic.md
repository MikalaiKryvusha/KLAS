# Bug 06 — голосовой ход умирает, когда ответ ядра без русских букв («56.», «OK.»)

**Статус:** 🔧 **крах устранён охранником, полное лечение ждёт владельца** — ход больше не падает, но
числовые и английские ответы KLAS пока **молчит**
**Компонент:** «РОТ» (Г1) — Silero v5 ru через `tools/voice-say.mjs` → `tools/voice/silero_say.py`
**Когда/контекст:** найден 2026-07-28 при перепроверке голосового тракта на новом движке b10167
(`plans/16`, хвост смены билда). Движок к дефекту отношения не имеет — он был всё это время.

## Симптом

Живой голосовой ход: вопрос «сколько будет семь умножить на восемь» → ядро отвечает `56.` → **весь
процесс `voice-talk` падает стеком**, ответ не озвучен, диалог оборван:

```
🎤 Ты: сколько будет семь умножить на восемь
🤖 KLAS: 56.
Error: РОТ упал: prepare_tts_model_input
    clean_text_list = self.process_simple_text(text)
  File "<torch_package_0>.multi_acc_v3_package.py", line 223, in process_simple_text
    raise ValueError
```

## Корневая причина (ПОДТВЕРЖДЕНА наблюдением)

Препроцессор Silero v5 ru (`process_simple_text`) требует в тексте **хотя бы одну кириллическую
букву**. Без неё он кидает голый `ValueError` (без сообщения). Проверено перебором:

| Текст | Результат |
|-------|-----------|
| `56` | ❌ ValueError |
| `56.` | ❌ ValueError |
| `OK.` | ❌ ValueError |
| `Ответ: 56.` | ✅ синтез |
| `42 плюс 14.` | ✅ синтез |
| `Минск.` | ✅ синтез |

То есть **цифры и латиница сами по себе не озвучиваются, а вместе с кириллицей — озвучиваются**.
Дефект не в цифрах как таковых, а в отсутствии русских букв во ВСЕЙ реплике.

Почему не поймали раньше: автономный `voice-roundtrip` гоняет 10 заготовленных РУССКИХ фраз, а живые
прогоны Г3 задавали вопросы, на которые ядро отвечало предложениями. Короткий фактический ответ
(«56.», «OK.», «Windows 11») в тесты не попадал ни разу — классическая дыра фикстуры.

## Лечение

### Применено (2026-07-28) — крах убран

1. **Охранник в `tools/voice-say.mjs`**: если в тексте нет кириллицы — не звать сайдкар, напечатать
   внятную причину и выйти **кодом 2** (отдельный код = «нечего произносить», не «РОТ сломан»).
2. **`tools/voice-talk.mjs` переживает этот случай**: `say()` возвращает `false`, ход печатает
   `(не озвучено: в ответе нет русских букв — bugs/06)`, тайминги и диалог продолжаются.

Проверено тем же прогоном, который падал: `node tools/voice-talk.mjs --wav ... ` → ядро снова ответило
`56.`, ход завершился штатно (`exit=0`), стека нет. [TESTED: 2026-07-28 · живой прогон каскада]

### НЕ применено — решение владельца (связано с уже зафиксированной жалобой)

Настоящее лечение — **нормализация текста перед TTS**, и она упирается в развилку уровня видения,
которую агент не решает один (владелец уже сказал по Г3: *«TTS не произносит английские слова, STT
пишет английское кириллицей»* — см. `STATUS.md`):

- **Числа → слова** (`56` → «пятьдесят шесть») — вариант однозначный, спорить не о чем.
- **Латиница → произношение** (`OK`, `Windows 11`, `GitHub`) — а вот это выбор БРЕНДА и UX:
  транслитерация («окей», «гитхаб»), английская фонетика вторым голосом или пропуск. Один правильный
  ответ отсутствует → в `/interview` вместе с остальной двуязычностью тракта, а не в код.

Пока решение не принято, KLAS на числовой ответ **молчит** — это честная деградация вместо падения,
но это не «готово».

## Радиус поражения

`tools/voice-say.mjs` (охранник) · `tools/voice-talk.mjs` (устойчивость хода) · планы `11` (Г1) и
`13` (Г3). Тот же охранник защищает и TTS-провайдера ядра OpenClaw (`tts-local-cli` → `voice-say.mjs`,
`plans/14`): там падение сайдкара точно так же роняло бы ход ноды.

## Решения, принятые без владельца

- **Код выхода 2 вместо нового флага** — минимум сущностей: вызывающему нужно отличить «нечего
  произносить» от поломки, и кода выхода для этого достаточно.
- **Проверка на кириллицу, а не на «есть ли буквы вообще»** — потому что перебор показал: латиница
  БЕЗ кириллицы тоже падает, значит критерий именно «есть русская буква».
- **Не стал делать нормализацию чисел явочным порядком**, хотя она бесспорна: она неразрывна с
  вопросом латиницы, а он владельческий. Разводить их в разные релизы — плодить полумеры.
