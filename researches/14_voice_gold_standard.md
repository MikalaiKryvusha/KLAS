## 1. Золотой стандарт сферы

### 1.1 Архитектура: каскад победил — но осознанно, а не по инерции

Развилка 2026 года — **каскад** (STT → LLM → TTS, наш путь) против **full-duplex speech-to-speech**
(единая модель, слушает и говорит одновременно).

| | каскад | speech-to-speech |
|---|---|---|
| выигрывает в | модульности, свободе выбора LLM, зрелости экосистемы, наблюдаемости | естественности разговора, паралингвистике (интонация, смех, вздохи), настоящем full-duplex |
| проигрывает в | двух точках сериализации: STT→LLM и LLM→TTS, каждая ждёт завершения предыдущей стадии | доступности production-grade решений |
| вердикт индустрии 2026 | **производственный выбор — каскад** | преимущества реальны, но операционно ещё не готовы |

**Что это значит для KLAS:** наш каскад — не отсталость, а мейнстрим. Но обе точки сериализации у
нас сейчас *полные*, а не потоковые (см. §4), и именно там лежит наш главный резерв.

### 1.2 Turn-taking: это ТРИ слоя, а не «тишина N миллисекунд»

Эталонная реализация очерёдности и перебивания — **трёхслойная**:

1. **Акустический VAD** — непрерывно оценивает вход, в том числе ПОКА агент говорит.
   OSS-эталон — **Silero VAD**.
2. **Endpointing** — решение «реплика закончилась»: классическое молчание **800–1200 мс** после
   последнего слова.
3. **Семантическое определение конца хода** — замена таймера тишины предсказанием завершённости
   ПО СОДЕРЖАНИЮ. Конкретика 2026: небольшой трансформер-детектор (~135M параметров, работает
   десятки мс на CPU, есть мультиязычный вариант) — у LiveKit; `smart-turn` — у Pipecat. Либо
   стриминговый STT, выдающий обучённый токен конца хода с настраиваемым порогом уверенности.

### 1.3 Barge-in (перебивание) — пять компонентов и жёсткий бюджет

Порядок: **VAD → триггер перебивания → flush TTS → отмена LLM → сохранение прерванного контекста.**

| параметр | эталонное значение |
|---|---|
| минимальная длительность речи для срабатывания VAD | 200–300 мс |
| порог энергии | −45…−35 dBFS |
| flush TTS | **< 60 мс** |
| отмена генерации LLM | **< 40 мс** |
| **общий бюджет barge-in** | **< 150 мс** |
| пауза между ходами, P95 | 200–450 мс |
| доля ложных перебиваний | целевая **< 2%**; выше 5% — «система кажется сломанной» |

### 1.4 ⚠️ AEC — обязательный слой, о котором забывают первым

**Эхоподавление (AEC) обязано стоять ПЕРЕД VAD.** Без него VAD слышит собственный голос агента из
динамиков и принимает его за перебивание — ассистент перебивает сам себя. Задержка AEC 10–30 мс
входит в общий бюджет. OSS-путь — WebRTC AEC3.

**Это прямо касается KLAS:** у владельца динамики и микрофон в одной комнате, без наушников. Любой
barge-in без AEC у нас не заработает в принципе. (Косвенное подтверждение из нашей же истории: вечер
2026-07-28 был потерян на том, что микрофон слышал то, что играло в колонках.)

### 1.5 Бюджет латентности: считать по стадиям, а не по среднему

Индустриальный ориентир — **~800 мс «голос-в-голос»**, P50 < 1.5 с, P95 < 5 с для каскада.
Ключевой принцип: **задержка НАКАПЛИВАЕТСЯ, а не усредняется**, поэтому бюджетируется каждая стадия:

| стадия | бюджет эталона |
|---|---|
| endpointing | 50–200 мс |
| финализация STT | 50–150 мс |
| **LLM time-to-first-token** | **150–500 мс — обычно доминирующая статья** |
| первый байт TTS | 75–200 мс |
| буферизация транспорта | 20–80 мс |

Совпадает с тем, что мы вывели сами в `researches/12`: главная метрика — **TTFA**, а не полное время
хода; 90%+ петли сидит в `LLM TTFT + TTS TTFB`.

### Режимы отказа, которые эталон называет заранее (грабли, оплаченные другими)

| Режим | Причина | Признак | Лечение |
|---|---|---|---|
| фоновый шум | амбиент выше порога | ложные перебивания | тюнинг порога энергии |
| посторонние голоса рядом | другой человек в комнате | агент прерывается | диаризация либо принять потерю |
| тихий пользователь | энергия < −50 dBFS | перебивание не срабатывает | автотюнинг порога на сессию |
| цикл «отменил-перезапустил» | cancel-restart > 10% | агент «дёргается» | поднять min-duration до 350 мс |
| тул-колл в полёте при перебивании | гонка | дедлок/таймаут | идемпотентные чтения — доводить, мутации — отменять |

## 5. Решение для KLAS (предложение агента, требует слова владельца)

Приоритеты владельца: стабильность → ум → скорость; минимум сущностей; приватность и офлайн.

**Что предлагаю в этом порядке — и почему именно так:**

1. **AEC первым, до всего остального.** Он ничего не даёт видимого сам по себе, но без него
   следующие два шага физически невозможны, а сделанные — придётся переделывать. Дёшево: WebRTC AEC3.
2. **Silero VAD + endpointing (800–1200 мс).** Убирает Enter из разговора — это самое заметное для
   человека изменение за наименьшие деньги. Бонус: **та же команда, чей TTS у нас уже стоит**, MIT,
   работает на CPU за миллисекунды ⇒ ноль новых сущностей по духу.
3. **Barge-in** по бюджету §1.3 (flush TTS < 60 мс, отмена ядра < 40 мс). Наш стриминг по фразам уже
   даёт точку разрыва — рвать есть что.
4. **Резерв латентности — строка 4, а не «модель поменьше».** Это уже дважды подтверждено замерами
   (`researches/12`): время уходит в префилл 20-тысячного системного промпта, а не в генерацию.
   Целиться надо в промпт и кеш, а не в размер модели.
5. **Full-duplex (Moshi) — НЕ БРАТЬ сейчас.** Индустрия прямо говорит: производственный выбор
   2026 года — каскад. Держать в поле зрения как горизонт для Jarvis.

**Чего делать НЕ предлагаю:** переписывать тракт на Pipecat/LiveKit. Они дают ровно те слои, что
перечислены выше, но тянут собственную рантайм-модель поверх нашей уже работающей и проверенной
бенчем. Дешевле взять из них ИДЕИ и по одной OSS-детали (Silero VAD, пороги smart-turn), чем
architecture-swap. Если владелец решит иначе — это развилка уровня видения, а не моя.

## 6. Открытые вопросы владельцу (в `/interview`)

1. **Убирать ли Enter из разговора?** VAD + endpointing делают диалог живым, но означают, что
   микрофон слушает ПОСТОЯННО. Для системы, чей принцип — приватность, это решение владельца, а не
   инженерное удобство.
2. **Нужен ли barge-in** (перебивать ассистента голосом), или для его сценариев хватает того, что
   ответы короткие?
3. **Стоит ли единый голос лицензии?** Настоящий кросс-язычный клон (`bugs/11` вариант C) сегодня —
   это XTTS-v2 под **CPML** (ограничивает коммерческое использование) либо F5-TTS под MIT. KLAS —
   MIT-проект.
4. **Куда целим бюджет латентности?** Эталон 800 мс на локальном железе с 20k системным промптом
   недостижим. Какая цифра для владельца означает «живой разговор»?
