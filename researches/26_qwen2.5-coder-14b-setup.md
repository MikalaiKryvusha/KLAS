## Бюджет VRAM — арифметика вместо желаний

KV-кеш на токен: 2 (K+V) × 8 KV-голов × 128 dim × 48 слоёв = 98 304 значения;
q8_0 ≈ 1.0625 Б/значение ⇒ **≈ 102 КиБ/токен**.

| Контекст | KV q8_0 | Итого (веса 9.79 ГиБ + KV + ~1 ГиБ буферы) | Вердикт для 16 ГиБ |
|----------|---------|--------------------------------------------|--------------------|
| 131 072 | ≈ 12.8 ГиБ | ≈ 23.5 ГиБ | ⛔ физически не помещается (профиль слабой сессии) |
| 32 768 | ≈ 3.2 ГиБ | ≈ 14.0 ГиБ | ⚠️ впритык: десктоп уже держит часть VRAM |
| **24 576** | ≈ 2.4 ГиБ | ≈ 13.2 ГиБ | ✅ выбран для профиля (влезает промпт Zoo Code ~15.5K + история) |
| 20 480 | ≈ 2.0 ГиБ | ≈ 12.8 ГиБ | ✅ запасной шаг вниз, если 24576 не встанет |

[NOT-TESTED] Пересобранный профиль (`-c 24576`) под нагрузкой не проверялся — на момент ревизии
GPU был занят (4.6/16 ГиБ). Проверка загрузкой + смоук — шаг Б1 в `plans/25`.

## Профиль llama-swap (текущий)

Живёт в `llama-swap/config.yaml`, ключ `"qwen2.5-coder-14b"` — там же комментарий с бюджетом VRAM.
Кратко: `-c 24576 -ctk q8_0 -ctv q8_0 -ngl 99 --flash-attn on --jinja`, сэмплинг 0.6/0.95/20.

## Подключение Zoo Code — исправлено

Правильный вход — **llama-swap на `http://127.0.0.1:8080/v1`** с `"model": "qwen2.5-coder-14b"`
(swap сам поднимет модель и выгрузит по ttl). ⛔ Совет исходной версии «напрямую к llama-server на
8081» — ошибка: **порт 8081 в KLAS занят Kiwix** (карта портов — `AGENT_GUIDE.md` → «Сборка»).

## Сэмплинг — унаследован, не проверен

`--temperature 0.6 --top-p 0.95 --top-k 20 --min-p 0`. Исходный документ сам с собой расходился
(в тексте «0.7/0.8 по официальной документации», в конфиге 0.6/0.95). При бенчах сверить с
`generation_config.json` модели на HF; до тех пор значения не трогать — иначе бенчи измерят
смену сэмплинга, а не модель.

4. Совет «напрямую на 8081» вёл в Kiwix.
5. Рядом лежали стенды с мёртвым путём `F:\LLMs\…` (без `KLAS`) и `tools/help.txt` с моджибейком —
